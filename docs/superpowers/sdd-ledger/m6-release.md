- **Fixed directly by the controller** (not deferred — it directly threatens the CI gate Task 10 is about to wire up, and it's a real production bug, not just a test flake): the Task 5 reviewer's first test run hit a real intermittent failure in `packages/cli/test/decisions.command.test.ts` — `EventLog`'s generated run/decision ids are plain nanoid-style strings with no guard against a leading `-`, and when such an id is passed positionally to a commander-based CLI command (e.g. `agentos approve <id>`), commander misparses the leading `-` as an unknown flag (`unknown option '-v7C...'`) instead of a positional argument. This affects real usage too, not just tests: any real user running `agentos approve <id>`/`reject <id>`/`logs <runId>` against an id nanoid happened to generate with a leading `-` (~1-in-64 per id, uniform 64-char alphabet) would hit the same misparse. Fixed (commit `85e40f2`) with a `genId()` wrapper in `eventLog.ts` that regenerates via `nanoid()` while the result starts with `-`, applied at all 4 call sites (`createRun`, `createDecision`, `sendMessage`, `schedule`). Added 2 new deterministic regression tests (`eventLog.genId.test.ts`, mocking `nanoid` to force the retry path and to confirm no retry when the first id is already safe) rather than relying on a probabilistic "generate many ids" test. Verified via a full clean-checkout simulation (`rm -rf packages/*/dist && CI=true pnpm install --frozen-lockfile && pnpm -r build && pnpm -r test && pnpm lint`) — 12+21+133+11+13 = 190 tests, all green, no regressions.
