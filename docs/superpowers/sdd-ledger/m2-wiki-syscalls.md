Review found a **Critical, empirically-exploitable** path-traversal vulnerability: `writePage`/`readPage` joined the caller-supplied path onto `wiki/` via `path.join`, which silently collapses `..` segments — a path like `../raw/x.md` skipped the literal `raw/`-prefix check (it doesn't start with `"raw/"`) and `path.join` resolved it right back into the immutable `raw/` directory, **overwriting a raw file**; `../../../../etc/x.md` escaped `osRoot` entirely. Reviewer demonstrated both exploits directly against the running code before any fix. Also **Important**: frontmatter/`links` fields were never secret-scanned (only `content` was), so a secret hidden in a `links` entry would be written verbatim into the page and `index.md`. Ruling: fixed directly (commit 60bff83) with a `resolveWikiPath()` helper used by both `writePage` and `readPage` — resolves the full path via `path.resolve` and verifies containment under a resolved `wikiDir()` (`full === wikiDirResolved || full.startsWith(wikiDirResolved + path.sep)` — the `+ path.sep` specifically closes the sibling-directory-prefix bypass class, e.g. `/os/wiki-evil` being mistaken for inside `/os/wiki`), kept the literal `raw/`-prefix check for its clearer error message, and widened secret-scanning to `[content, ...links].join('\n')`. Added 4 regression tests. A dedicated adversarial re-review (throwaway exploit tests: traversal into raw/, traversal fully outside osRoot, absolute-path injection, backslash-encoded traversal, sibling-prefix bypass attempt, edge cases `.`/`''`) confirmed the fix closes the hole with no new bypass and no regressions (67/67 kernel tests, `tsc --noEmit` clean, no public signature changes). — Why `path.resolve`-based containment over a smarter path-sanitizing library: this is the exact pattern Node's own docs recommend for this class of bug, needs no new dependency, and is easy to audit. — Cost if wrong: none identified; two independent adversarial reviews (implementer's own review + the fix's re-review) tried to break it and couldn't. Minor deferred (not fixed, lower stakes): `listUnindexedRaw`'s "is it indexed" check is a raw substring test against all of `index.md` (`!indexMd.includes(f)`) rather than checking the path appears specifically as a `sources:` reference — a raw filename mentioned in unrelated prose would cause a false "already indexed" and skip it from the unindexed list. Complete (commits 4d94e83..faff15c + 60bff83, review found 1 Critical + 1 Important fixed, both re-verified); merged into m1-kernel-core.
