- Task 5 (retry/backoff + missed-routine `ops.alert`): implemented directly. **Found and fixed a real bug in the plan's own reference design**, not just its test: the `every:`-interval handler unconditionally refreshed `lr.nextRunAt` to `now + everyMs` on *every* timer tick regardless of whether the previous fire's execution had actually completed — so for a genuinely hung/stuck exec, `nextRunAt` would perpetually trail ~1 interval behind "now" and `checkMissedRoutines`'s `now > nextRunAt + grace` comparison could mathematically never trip. Confirmed empirically with a standalone fake-timer repro script before touching any implementation code (logged interval/tick timestamps directly). Fixed by adding an `inFlight` flag to `LoadedRoutine`, gating the nextRunAt/missedAlerted refresh on the *previous* fire having settled, and giving `every:`-routines their own tracked execution path (`runTrackedEveryRoutine`) so `trigger()` knows when to flip `inFlight` back off. **Also found the plan's own test had unsatisfiable arithmetic**: with `MIN_GRACE_MS=60_000` and `nextRunAt` pinned at ~2s after the fix, the "missed" threshold is ~62s, but the plan's test only advanced fake timers to a 61s total elapsed, and even the closest 15s-tick boundary (60s) falls short — no value of `nextRunAt` bounded below by 0 can make `60000 > nextRunAt + 60000` true. Fixed by advancing to 75s (the next 15s tick boundary past the 62s threshold) in the test, matching the reason the routine should be flagged, not just contorting the assertion. Ruling: both fixes are the smallest correct changes — the `inFlight` gate doesn't change behavior for cron/on-event/manual-runNow routines (they don't set `everyMs`), and the test-timing fix only changes when a already-correct assertion is exercised, not what it checks. — Cost if wrong: the missed-routine detector is new/unused by any other code yet (M3 Task 9's routines API is the first real consumer), so a residual edge case here has no blast radius beyond this file. All 3 tests pass, 113 kernel tests green. Merged as 6167d32.
