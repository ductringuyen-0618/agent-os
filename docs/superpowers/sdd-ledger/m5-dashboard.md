  - **Gap**: contract §7 lists `GET /api/skills`, `GET /api/agents`, `GET /api/costs` as base routes (not a Task 13 "contract addition" — those were already committed to in the contract from the start), but grep across every M1-M4 plan found no task that ever implements them. Every dashboard panel depending on them (Agents since Task 6, Skills's list view since Task 10, Costs since this task) has only ever been tested against the mock fetch layer, never a real kernel. Ruling: implement all three directly in `server.ts` as part of landing Task 13 (the natural place — this is exactly "finishing the kernel API surface the dashboard needs"), rather than opening a new task or leaving them broken. `GET /api/skills` and `GET /api/agents` scan `os/skills/` and `os/agents/` subdirectories; agent status is derived from the most recent non-terminal (`running`/`wrapping_up`/`blocked`) `Run` for that agent name; `GET /api/costs` filters `EventLog.listRuns()` to the requested day window. `lastScore` is left undefined for every skill — no scoring/eval-loop mechanism exists yet in this codebase (that's M6 territory), so there's nothing to source it from. Cost if wrong: low — these are read-only derivations from data the EventLog and filesystem already hold, easy to correct later if the shape needs adjusting. 3 new server tests (skills/agents list, costs window), kernel 131/131 green.
  - **Bug**: `dashboardDist`'s path in the Task 13 reference code was computed as `path.resolve(fileURLToPath(import.meta.url), '../../../../dashboard/dist')` — a fixed 4-level `../` climb from `import.meta.url`. This happens to be correct when `server.ts` runs unbundled under vitest (`packages/kernel/src/api/server.ts`, which has an extra `api/` directory level) but is one level too shallow for the real bundled `packages/kernel/dist/index.js` (tsup flattens the whole package into one file, dropping the `src/api/` nesting) — confirmed empirically: running the actual built kernel (`node tools/e2e-kernel.mjs`, itself only built while chasing Task 14) logged `"root" path "/home/user/agent-os/dashboard/dist" must exist` and 404'd `GET /`, while `pnpm --filter kernel test` passed the identical-looking assertion the whole time. This is the same class of bug as M2's `mcpConfig.ts` binPath fix and M4's adapters/types dual-bundle issue — a path or type computed relative to `import.meta.url` that silently assumes one specific build layout. Fixed by walking up from the file to the nearest `package.json` instead of hardcoding a level count, which is correct regardless of bundling depth. Re-verified both contexts (built `dist/index.js` via `node tools/e2e-kernel.mjs` + curl, and `pnpm --filter kernel test`) pass after the fix.
